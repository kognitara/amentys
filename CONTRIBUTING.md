# Contributing to Amentys

Thank you for your interest in Amentys! 

Because Amentys is designed as an inseparable monolith (kernel, storage, and user interface merged into a single entity), 
our contribution workflow is strictly tailored to protect the project's unity and prevent fragmentation.

By contributing to Amentys, you help build a single, unified, and powerful official ecosystem.

## How to Contribute

1. Report Bugs or Suggest Features

If you find a bug or have an idea for a new monolithic feature:

Check the existing Issues to ensure it hasn't been reported yet.

Open a new Issue describing the problem or the feature in detail.

For feature requests, explain how it fits into the unified Amentys architecture without breaking the monolith concept.

2. Proposing Changes (Pull Requests)

To submit code or documentation changes, follow these steps:Keep it Monolithic: 

Ensure your feature integrates seamlessly into the unified kernel/storage/UI structure. 

Loose or independent components that promote modular fragmentation will be rejected.

Create a Private Branch: Work on your changes within a private or temporary development environment.

Write Clean Code: Follow the official Amentys coding guidelines.

Ensure your code is thoroughly documented.

Submit a Pull Request: Open a PR against the main or development branch of the official Amentys repository.

Describe Your PR: In the PR description, clearly explain:

What problem this contribution solves.

How it impacts the system's performance or unified architecture.

A sentence confirming your agreement with the ASAL license terms.

## Code Review Process

All submissions will be reviewed by the Original Author or designated maintainers.

We look for architectural consistency, stability, and alignment with the project's vision.

You may be asked to modify your code or adjust its implementation before it is merged into the official repository.

Thank you for dedicating your time and energy to making Amentys the ultimate unified system!
